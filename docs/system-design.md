# 个人投资管理系统设计（V1）

> 状态：产品与架构草案
> 目标用户：单个个人投资者
> 核心定位：统一账本、看清收益与风险、约束投资纪律、支持持续复盘
> 说明：系统提供记录、计算和决策支持，不代替投资建议。

## 1. 设计目标

这套系统不是行情终端，也不是自动交易程序。它首先要回答五个问题：

1. 我现在拥有什么，分布在哪里？
2. 我的真实收益是多少，来自资产上涨、汇率还是现金流？
3. 当前承担了哪些集中度、回撤、流动性和币种风险？
4. 当前仓位是否偏离既定策略，需要做什么？
5. 当初为什么买卖，事后判断和过程质量如何？

V1 适合股票、ETF、基金、债券、现金、存款、黄金、虚拟货币和少量非标资产；支持多账户、多币种。虚拟货币首版覆盖现货币种、稳定币、交易所账户和自托管钱包，不包含 NFT、DeFi 头寸拆解及链上衍生品。期权、期货、融资融券、复杂税务和自动交易不进入首个版本。

## 2. 核心原则

- **账本为真源**：交易、转账、分红、费用等不可变流水是持仓和收益的计算基础。
- **本地优先**：数据默认保存在本机，行情和汇率属于可替换的外部数据。
- **口径明确**：每个指标都显示时间范围、基准、币种和计算口径。
- **事实与判断分离**：市场数据、账户事实与投资假设分别存储。
- **少而有用**：首页优先展示需要关注和行动的信息，而不是堆积图表。
- **可追溯**：导入、修改、价格覆盖和分类调整都有来源及审计记录。
- **渐进自动化**：先保证手工可用，再增加 CSV 导入、行情同步和自动规则。

## 3. 系统结构

```text
数据输入层
  ├─ 手工录入
  ├─ 券商/银行/交易所 CSV 导入
  ├─ 定时 API 数据采集
  └─ 行情、汇率、链上与基准数据
          ↓
统一投资账本
  ├─ 账户
  ├─ 标的与分类
  ├─ 交易/现金事件
  └─ 价格与汇率快照
          ↓
计算引擎
  ├─ 持仓与成本
  ├─ 收益与归因
  ├─ 资产配置
  └─ 风险与再平衡
          ↓
使用层
  ├─ 总览仪表盘
  ├─ 组合与标的详情
  ├─ 投资计划和决策日志
  └─ 周/月/季度复盘
```

## 4. 功能模块

### 4.1 总览 Dashboard

首页只放最重要的信息：

- 净资产、投资资产、现金及当日数据更新时间；
- 本月、本年、成立以来收益率和盈亏额；
- 资产类别、账户、币种和地区配置；
- 当前回撤、历史最大回撤、单一标的最大权重；
- 相对目标配置的偏离；
- 待处理事项：缺失价格、未分类流水、策略越界和复盘到期；
- 最近决策与即将执行的投资计划。

首页不默认展示刺激短线行为的分时行情和盈亏排行榜。

### 4.2 账户与资产

- 账户：券商、银行、基金平台、养老金、虚拟货币交易所、自托管钱包、其他；
- 账户属性：机构、账户类型、基础币种、是否计入净资产、启用状态；
- 资产：股票、ETF、基金、债券、现金、定期存款、黄金、虚拟货币、稳定币、其他；
- 虚拟货币标识：交易代码、链、合约地址、精度和价格计价币种；同名跨链资产不得只按代码合并；
- 自定义标签：核心/卫星、国家地区、行业、主题、风险等级、流动性等级；
- 支持同一标的在多个账户持有。

### 4.3 统一账本

标准事件类型：

- 买入、卖出；
- 入金、出金、账户间转账；
- 分红、利息、资本返还；
- 质押奖励、空投、链上转入与转出；
- 手续费、税费、管理费；
- 网络 Gas 费、交易所提币费；
- 拆股、合股、送股、换股；
- 价格调整、余额调整；
- 非交易资产估值更新。

关键规则：

- 所有金额保留原始币种，同时按交易日汇率换算为报告币种；
- 账户间转账必须成对记录，不计作组合外部现金流；
- 交易所与钱包之间的虚拟货币划转按内部转账处理，转出数量与到账数量之差记为网络费用；
- 导入流水使用“来源 + 外部流水号”去重；
- 已确认流水不直接覆盖，修改通过冲销和重记完成；
- 每次导入先预览、匹配和校验，再正式入账。

### 4.4 持仓与成本

- 当前数量、市值、平均成本、未实现盈亏、已实现盈亏；
- 默认使用移动加权平均成本，同时预留 FIFO 分批成本能力；
- 展示原币和统一报告币种；
- 支持历史任意日期的持仓快照；
- 现金本身作为一种资产持仓，避免余额与账本脱节。
- 虚拟货币按可配置的日结时区生成每日快照，默认使用报告时区的 00:00 作为日界线。

### 4.5 收益分析

同时保留三种视角：

- **盈亏额**：回答赚了或亏了多少钱；
- **资金加权收益率 XIRR**：回答个人投入资金实际获得的年化回报；
- **时间加权收益率 TWR**：剔除入金出金影响，用于评价投资组合和与基准比较。

收益分解：

```text
总收益 = 已实现盈亏 + 未实现盈亏 + 分红/利息 - 费用/税费 + 汇率影响
```

支持按账户、资产类别、标的、币种、地区和自定义标签切片；支持与一个或多个基准比较。所有收益页面必须显示区间、报告币种、价格来源以及是否包含分红。

### 4.6 风险与配置

V1 采用个人投资者真正能执行的风险指标：

- 单一标的、行业、地区、币种和账户集中度；
- 虚拟货币总仓位、单币种、稳定币、交易所托管和自托管敞口；
- 当前回撤和历史最大回撤；
- 波动率、下行波动率；
- 现金比例和未来 3/6/12 个月已知资金需求覆盖；
- 高风险资产比例与策略上限；
- 24 小时市场的价格陈旧、流动性和托管风险提示；
- 组合与基准的相关性、Beta（数据足够时）；
- 目标配置偏离与再平衡建议。

再平衡默认采用“阈值触发 + 新资金优先”：

```text
偏离值 = 当前权重 - 目标权重
触发条件 = |偏离值| >= max(绝对阈值, 目标权重 × 相对阈值)
```

系统只给出调整缺口和可选方案，不自动下单。

### 4.7 投资策略与决策日志

系统内置一份个人投资政策声明（IPS）：

- 投资目标与期限；
- 报告币种；
- 目标资产配置及上下限；
- 最大可接受回撤；
- 单一标的和高风险资产上限；
- 应急资金要求；
- 允许与禁止的工具；
- 再平衡和复盘频率。

每次重要买卖可关联一条决策日志：

- 决策日期、标的、操作与仓位目标；
- 投资逻辑和关键假设；
- 估值依据与预期区间；
- 风险、反方观点和证伪条件；
- 计划持有期、退出条件和复盘日期；
- 决策信心、实际结果、事后评价和经验。

评价重点分为“结果质量”和“过程质量”，避免只按盈亏判断决策好坏。

### 4.8 复盘与提醒

- 每周：处理未分类流水、缺失价格和异常余额；
- 每月：核对账户、更新净资产、检查配置偏离和现金计划；
- 每季度：比较基准、归因收益、复核持仓逻辑和风险预算；
- 每年：更新 IPS、目标配置、长期目标和系统数据备份。

提醒仅围绕可执行事项：复盘到期、策略越界、现金不足、数据异常和文档到期。

### 4.9 定时 API 数据采集

系统提供可配置的后台采集任务，用于定期录入行情、汇率、基准、虚拟货币价格，以及用户主动授权的账户余额和流水。币种为 USD/HKD 的股票与 ETF 会自动接入美股/港股公开行情，默认每 5 分钟采集，前端每 60 秒读取最新结果；公开行情可能存在延迟，不作为交易下单依据。默认只启用公开市场数据；券商或交易所账户接口必须使用只读权限，系统不接受带下单或提币权限的密钥。

每个数据源可设置：

- 数据类型、API 地址、认证方式和来源优先级；
- 采集范围，例如标的列表、账户列表或交易对；
- 执行频率、时区、超时、最大重试次数和启停状态；
- 增量同步游标、历史回补起止日期和单次请求上限；
- 限流策略、数据陈旧阈值和失败通知方式。

默认调度建议：

- 股票、基金、债券和基准收盘价：对应市场收盘后每日一次；
- 汇率：每日一次；
- 核心报告币种可在主流货币中切换；首次启动初始化主流货币交叉汇率，之后允许用户手动刷新；
- 虚拟货币价格：每 15 分钟一次，日终价格单独固化；
- 账户余额和流水：每小时一次，或由用户按需触发；
- 历史数据回补：低优先级分批执行，避免触发供应商限流。

采集流程：

```text
调度触发 → 拉取原始响应 → 校验与标准化 → 幂等去重
        → 写入暂存区 → 业务规则校验 → 正式入账 → 记录运行结果
```

可靠性要求：

- 使用“数据源 + 外部记录 ID”，无外部 ID 时使用稳定内容哈希实现幂等；
- 原始响应保留校验哈希和最小必要快照，便于追溯，但敏感字段必须脱敏；
- 网络错误采用指数退避重试，鉴权错误立即停用任务并提示用户；
- 单次失败不得覆盖最近一次有效数据；连续失败或数据过期进入数据质量中心；
- 应用重启后补跑错过的关键任务，历史回补与实时更新互不重复；
- 自动写入账户流水前先经过匹配规则；无法确定的记录进入待确认区；
- 支持手工立即同步、暂停、重跑失败批次和查看每次运行日志。

## 6. 核心数据模型

| 实体 | 关键字段 | 说明 |
|---|---|---|
| `accounts` | id, name, institution, type, base_currency | 投资、现金、交易所和钱包账户 |
| `instruments` | id, symbol, name, asset_type, currency, exchange, network, contract_address | 可交易或估值标的；支持跨链资产唯一识别 |
| `transactions` | id, type, trade_at, settle_at, source, external_id | 不可变业务事件头；不绑定单一账户，以支持跨账户事件 |
| `transaction_legs` | transaction_id, account_id, instrument_id, leg_type, quantity, unit_price | 一笔事件的资产、现金和费用分录 |
| `prices` | instrument_id, date, close, currency, source | 日频价格，可人工覆盖 |
| `fx_rates` | base, quote, date, rate, source | 汇率快照 |
| `classifications` | instrument_id, dimension, value, valid_from | 支持分类历史变化 |
| `targets` | dimension, value, target_weight, min_weight, max_weight | 目标配置和边界 |
| `benchmarks` | instrument_id, weight, valid_from | 单基准或复合基准 |
| `investment_theses` | instrument_id, thesis, risks, invalidation, review_at | 投资逻辑 |
| `decision_logs` | action, decided_at, rationale, confidence, outcome | 重要决策记录 |
| `reviews` | period_type, period_start, period_end, summary | 周期复盘 |
| `import_batches` | source, imported_at, checksum, status | 导入和追溯 |
| `data_sources` | id, name, type, priority, credentials_ref, enabled | API 数据源配置，密钥只保存安全凭据引用 |
| `sync_jobs` | id, data_source_id, interval_seconds, timezone, cursor, retry_policy | 定时采集任务定义 |
| `sync_runs` | id, job_id, started_at, finished_at, status, stats, error | 每次执行结果与审计信息 |
| `staged_records` | sync_run_id, external_id, payload_hash, normalized_data, status | API 暂存、幂等去重和人工确认记录 |
| `audit_logs` | entity_type, entity_id, action, before, after | 关键修改审计 |

账本采用“交易头 + 多分录”结构。例如买入股票会同时减少现金、增加证券数量，并记录手续费。这比为每种交易设计孤立字段更容易处理转账、换股和公司行动。

## 7. 关键计算口径

### 7.1 组合市值

```text
标的市值（报告币种）= 持仓数量 × 当日价格 × 当日汇率
组合市值 = 所有标的市值之和
```

无当日价格时使用最近一个有效交易日价格，并明确标记“价格陈旧”。超过可配置天数后，该估值进入数据异常列表。

虚拟货币为 24 小时连续市场，日收益采用统一日结时区内的日终价格计算；系统必须记录价格源、交易对和换算路径，避免不同交易所或稳定币报价被静默混用。

### 7.2 现金流边界

- 外部入金和出金是组合外部现金流；
- 账户间转账不是组合现金流；
- 分红、利息、买卖和费用是组合内部变化；
- 是否计入组合的账户变化时，需要生成边界调整事件。

### 7.3 数据完整性校验

- 任一交易的分录按币种换算后必须平衡；
- 持仓数量不能因普通卖出变为负数；
- 账户现金余额可与机构月结单对账；
- 交易所和链上余额可与最新只读 API 或链上快照对账；
- 同一来源流水不得重复导入；
- 收益计算区间内的价格和汇率覆盖率必须可见。

## 8. 推荐技术方案

采用本地 Web 应用，兼顾可维护性和未来扩展：

- 前端：React + TypeScript；
- 后端：Rust + Axum；
- 数据访问：SQLx + SQLite，启用 WAL；
- 金额与数量：十进制定点数，数据库以规范化文本保存，禁止使用二进制浮点数；
- 计算：Rust 领域服务；大规模历史序列分析可按需引入 Polars；
- 图表：ECharts；
- 数据迁移：SQLx migrations；
- 定时任务：Tokio 后台任务 + 持久化调度表，随本地服务启动并支持错过任务补跑；
- 测试：Cargo test + Playwright；
- 部署：本机一键启动，后续可封装为桌面程序。

选择 SQLite 是因为单用户无需维护数据库服务，文件级备份简单。应用层仍保持数据库抽象，以便未来迁移 PostgreSQL。

安全与备份：

- 默认仅监听 `127.0.0.1`；
- 不保存券商登录密码；
- API 密钥进入本机安全凭据存储，不写入数据库或日志；券商和虚拟货币交易所仅允许配置只读密钥；
- 每日增量备份、每月完整备份，备份包可选加密；
- 支持导出 CSV/JSON，避免数据被应用锁定；
- 恢复流程必须定期验证，而不只检查备份文件存在。

## 9. MVP 范围

首个可用版本包含：

1. 券商、银行、交易所、钱包账户，以及标的和报告币种设置；
2. 买卖、入出金、转账、分红、利息、质押奖励、空投和各类费用录入；
3. CSV 通用模板导入、定时 API 采集、去重和预览；
4. 当前持仓、成本、市值和盈亏；
5. XIRR、TWR 和基准对比；
6. 资产配置、集中度、回撤和再平衡偏离；
7. IPS、投资逻辑、决策日志和月度复盘；
8. 数据质量中心、备份和全量导出。

暂不包含：

- 自动交易和券商账户密码托管；
- 实时行情；
- 期权、期货和复杂衍生品定价；
- NFT、DeFi 流动性池和链上衍生品的自动拆解；
- 自动生成报税表；
- 多用户、权限和云端协作；
- AI 自动给出买卖结论。

## 10. 分阶段落地

### 阶段 A：账本可用

建立数据库、基础设置、手工流水、CSV 导入、持仓和对账。验收标准是选取一个真实账户，能够从期初余额完整还原当前证券或虚拟货币数量及现金余额。

### 阶段 B：组合看清

加入定时 API 采集、行情/汇率、虚拟货币价格、历史估值、XIRR、TWR、配置、回撤和基准。验收标准是同一时间区间的期初、现金流、期末市值和收益能够相互勾稽，且同步失败不会污染最近一次有效数据。

### 阶段 C：纪律闭环

加入 IPS、目标配置、再平衡、决策日志和周期复盘。验收标准是系统能明确指出策略偏离、到期复盘和需要采取的动作。

### 阶段 D：自动化与完善

增加券商与虚拟货币交易所专用适配器、链上只读查询、行情源切换、自动分类、备份计划和复杂资产支持。

## 11. 开发前需要最终确认的个人参数

这些参数不阻塞原型开发，但会影响正式数据口径：

- 默认报告币种（例如 CNY、USD、HKD）；
- 实际使用的券商、银行和账户类型；
- 涉及的市场、虚拟货币交易所/钱包和资产类别；
- 成本法偏好（移动平均或 FIFO）；
- 主要业绩基准；
- 是否将住房、保险、养老金等纳入净资产；
- 目标配置、风险边界和复盘频率；
- 数据是否允许调用外部行情 API；
- API 数据的期望更新频率，以及是否允许使用账户只读密钥同步余额和流水。

## 12. 第一版成功标准

系统投入使用后，用户应能在 10 分钟内完成一次月度更新，并在一个页面内看清：

- 总资产、持仓与现金是否准确；
- 本期真实收益及主要来源；
- 是否偏离目标配置或风险边界；
- 哪些数据、决策或复盘需要处理；
- 下一步行动是什么，以及为什么。
